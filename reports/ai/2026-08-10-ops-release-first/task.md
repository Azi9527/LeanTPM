## 需求理解

| 类型 | 当前理解 |
|---|---|
| 真实问题 | 当前发布后需要手动刷新，发布状态与 Agent 状态缺少连续可见性。 |
| 明确需求 | 发布功能优先；系统监控、自动修复和 PushPlus 后续实现。 |
| 涉及对象 | 运维操作员、发布记录、Agent 状态、审计时间线。 |

| 必须确认 | 无；本轮只修改源码并运行本地测试，不部署。 |
| 默认假设 | 保持现有 API，不新增服务器权限；认证令牌仍只保存在页面内存。 |
| 假设影响 | 页面刷新会终止自动轮询并清除令牌，符合现有安全合同。 |

## 验收标准

```text
Given 运维身份已认证且发布记录进入 QUEUED 或 AGENT_VERIFIED
When 页面完成最终确认或操作员保持页面打开
Then 页面按固定低频间隔自动刷新发布记录、Agent 状态与审计时间线
And 只有服务端返回 DEPLOYED 才显示“生产部署成功”

Given 发布进入 DEPLOYED 或 FAILED
When 自动刷新读取到终态
Then 停止针对该发布的自动跟踪，并显示明确终态提示

Given 页面未认证、身份失败或浏览器页面不可见
When 到达轮询时间
Then 不发起受保护 API 请求，避免无效请求和后台持续轮询

Given 自动刷新遇到临时网络或服务异常
When 单次刷新失败
Then 保留现有页面数据，显示可恢复提示，不伪报发布失败
```
