# 组织工段类型兼容扩展

## 基本信息

- 任务类型：修复 / 兼容扩展
- 任务目标：在现有组织管理中增加独立“工段”类型，并兼容工厂→车间→工段→班组与车间→班组两种结构。
- 工作目录：`C:\Users\Mayn\.codex\worktrees\fca1\LeanTPM`
- 可信基线：`2185536ea9da0a323b27f53dcf849b818ea19069`（detached worktree）
- 范围：组织主数据 UI/API 校验、父子层级、人员关系负责人显示与内部负责人类型映射、相关测试。
- 非目标：数据库结构迁移、现有组织数据改写、生产部署、服务重启、角色体系重构。

## 需求理解

| 类型 | 当前理解 |
|---|---|
| 真实问题 | 组织类型下拉框只有“产线”，没有客户实际使用的独立“工段”类型。 |
| 明确需求 | 增加 `SECTION`（显示“工段”）；工段可位于车间下，班组可位于工段或直接位于车间下。 |
| 涉及对象 | 组织行、组织保存请求、组织层级校验、负责人字段、人员与组织关系页。 |
| 涉及模块 | `frontend` 组织管理/人员关系；`backend` masterdata/system。 |
| 可能歧义 | “工段”与现有 `LINE` 历史数据并存。 |
| 必须确认 | 无；用户已明确要求独立类型，且要求没有工段的车间允许直接挂班组。 |
| 默认假设 | 新内部代码使用 `SECTION`；旧 `LINE` 保持“产线”，不自动转换。 |
| 假设影响 | 新旧组织可以并存；无数据库迁移，回滚只需撤销代码。 |


## 2026-08-10 追加需求：组织类型不受层级限制

- 真实问题：页面已能选择“工段”，但后端仍按父级组织类型校验，旧运行进程还会把 `SECTION` 判为非法类型。
- 明确需求：组织树任意层级均可选择全部组织类型；新增和修改使用相同规则。
- 保留约束：组织类型仍必须来自受支持枚举；上级组织必须存在且在当前数据权限内；编辑时不得形成循环引用。
- 移除约束：不再限制某种组织类型只能挂在特定父级类型下；`parentId=0` 仅表示根，不再强制根类型必须为企业。
- 非目标：不修改数据库结构、不改写现有组织数据、不部署或重启云服务。
- 风险：L2。GitNexus 对 `assertOrganizationParent` 的上游影响为 LOW，直接调用方仅组织新增与组织修改；因前后端合同共同变化，治理等级保持 L2。

```text
Given 管理员新增或编辑任意组织节点
When 展开组织类型并选择任一受支持类型后保存
Then 后端不因父级类型或当前层级拒绝请求
And 上级不存在、越权或形成循环时仍拒绝
```
