# LeanTPM 正式源码收口与独立运维后台目标

## 1. 目标与边界

- 唯一正式源码目录：`D:\codex\LeanTPM`。
- 可信基线：`2185536ea9da0a323b27f53dcf849b818ea19069`。
- 先完成：源码收口、云端人工修复源码化、正式工具链/发布包闭环、External Caddy 两项安全修复。
- 随后实现独立运维后台，把发布流程收敛为“上传文件 → 自动校验/预检 → 展示计划 → 人工确认 → 执行 → 健康/审计 → 受控回滚/恢复”。
- 本目标暂缓全面云端业务自动回归和完整备份恢复演练；它们仍是正式验收项，但不阻塞独立运维后台的代码开发。
- 未经单次明确确认，不修改生产数据库、Windows Service、Caddy、防火墙、证书或公网流量。

## 2. 需求与验收

### 2.1 正式源码收口

```text
Given D 盘主工作树与 C 盘 Codex 工作树都基于同一可信提交，且 D 盘含用户未提交文件
When 按模块生成、检查并应用精确补丁
Then 已验证的后端、无 Redis、发布平台与 APP 代码进入 D 盘
And 用户文件不被覆盖、删除、暂存或格式化，C 工作树在验证完成前保留
```

### 2.2 云端人工修复源码化

```text
Given 当前云服务器依靠 MapperScan、构造器注入、MySQL URL、服务身份和 ACL 等人工修复运行
When 从 D 盘源码执行 clean build 和部署资产验证
Then 不再依赖服务器上手工修改过的 class/JAR/starter/Caddyfile
And 新产物可由固定工具链和同一输入重复生成、验证并回滚
```

### 2.3 独立运维后台

```text
Given 操作者拥有批准的签名发布包且通过独立运维身份认证
When 上传文件
Then 后台仅保存到隔离 staging，自动校验 schema、签名、哈希、版本、兼容性、主机和容量
And 在人工确认前不停止服务、不写数据库、不切换指针

Given 预检通过且操作者确认精确计划摘要
When 执行发布
Then 只调用固定白名单动作并实时记录状态、日志和哈希链审计
And 失败立即停止，按阶段提供受控回滚或恢复，不接受任意 shell/SQL/路径/服务名
```

## 3. 影响与风险

- 风险等级：L4。
- GitNexus 当前候选：78 个已跟踪文件、156 个已索引符号、12 条受影响流程，总体 HIGH。
- `AuthService`：5 个上游影响（3 个直接）；登录、会话和安全状态受影响。
- `DatabaseIdempotencyStore`：1 个直接上游影响；写请求幂等受影响。
- `AppReleaseService.release`：关联 latest/QR code 发布流程；现有业务 APP 发布功能不能直接扩权为主机发布控制面。
- 新增 PowerShell 发布脚本的图影响不完整，继续按 L4 源码边界、行为 harness 和独立审查治理。
