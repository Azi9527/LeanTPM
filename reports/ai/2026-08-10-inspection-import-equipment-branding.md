# 设备、导入模板与点检标准改进任务

## 需求范围

1. 设备编码允许安全的中文编码（例如 `铜精选#1`），编辑保存不再被旧的纯英文正则拒绝。
2. 用户、设备、点检、OEE 四类 Excel 导入模板在必填列标题中显示 `*`，并继续兼容旧模板。
3. 点检项目导入模板增加中文填写规范，明确必填/选填、自动编码及中文枚举。
4. 侧边栏和页面图标只展示企业 Logo 左侧图形标识，避免完整横版 Logo 被裁切。
5. 点检项目支持“共享标准”（不限定组织）。
6. 新建点检项目默认：标准分钟 2、最多照片 2、单张上限 5 MB。

第 7 项没有需求内容，本任务不做推断。

## Given / When / Then

- Given 设备编码由中文、字母、数字及安全分隔符 `._#-` 组成，When 新增/编辑设备，Then 后端校验通过；斜杠、空白和控制字符仍拒绝。
- Given 下载任一导入模板，When 查看表头，Then 必填列带 `*`；When 上传旧版无星号模板或新版模板，Then 均可识别。
- Given 下载点检项目模板，When 查看填写规范和示例，Then 用户能用中文枚举填写并区分必填、选填和自动生成项。
- Given 页面在窄尺寸展示品牌，When 渲染侧边栏 Logo 与站点图标，Then 仅显示左侧图形且无裁切残字。
- Given 新增/编辑点检项目，When 选择共享标准，Then `organizationId` 可为空并在列表显示“共享标准”；已有组织专属标准保持不变。
- Given 打开新增点检项目，When 表单初始化，Then默认值为 2 分钟、2 张、5 MB；编辑已有记录不覆盖原值。

## 影响与风险

- 风险等级：L2（跨后端校验、Excel 合同、前端表单与品牌资源）。
- 数据库结构：预计不变；点检项目现有 `organization_id` 已可为空，需由测试确认。
- API 合同：`SaveItemRequest.organizationId` 从必填改为可空；其他字段不变。
- 兼容性：导入解析器必须同时接受带星号与无星号表头；中文枚举只作为新增别名，英文旧值继续可用。
- 安全边界：设备编码只扩展 Unicode 字母/数字与有限分隔符，不接受路径分隔符或空白。

## 登录失败提示补充

- 需求：本地前端无法连接后端时，不得只显示“登录失败”，应明确提示后端未启动或网络不可达；后端返回 HTTP 错误时应显示服务端消息或可识别的状态说明。
- Given 本地后端没有监听，When 用户提交登录，Then 页面提示“无法连接后端服务，请确认后端已启动并检查网络”。
- Given 代理或后端返回 5xx 且没有标准 JSON 消息，When 用户提交登录，Then 页面提示后端服务暂时不可用并显示 HTTP 状态。
- 风险：L1，前端登录错误展示；不修改认证、令牌、账号锁定或后端接口。
- 变更前 GitNexus：`LoginView.submit` 与 `auth.signIn` 均为 LOW，无上游调用者或受影响执行流。
- 根因复核：`127.0.0.1:18080` 未监听，`127.0.0.1:4173/api/v1/public/branding` 返回 HTTP 500，证明本地前端代理无法连接后端；未据此判定为账号或密码错误。
- 测试先行：`node --test tests/login-error-contract.test.mjs` 在实现前失败、实现后 `1/1` 通过。
- 前端验证：`npm run typecheck` 通过；`npm run build` 通过（仅保留既有大分块体积提示）。
- 浏览器验证：重新构建并刷新 `http://127.0.0.1:4173/login?redirect=/dashboard`，页面资源加载正常；未代替用户提交已记忆的敏感登录凭据。
