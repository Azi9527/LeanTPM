# 点检流程与业务可读性整改验证报告

## 1. 范围与风险

- 任务风险：L4（涉及点检方案版本、计划持久化、任务创建合同、规则校验与多页面交互）。
- 本轮范围：点检项目、点检方案、点检计划、手工点检任务、提醒规则、发送记录、操作记录和 Excel 导出命名。
- 非目标：不写业务数据库，不清理或覆盖用户未提交内容，不提交、不推送、不部署。
- 工作区说明：仓库已有大量未提交改动。GitNexus 对整个未提交工作区判定为 `CRITICAL`（160 个文件、1016 个符号、120 条流程）；本轮仅在上述范围内做增量修复。

## 2. 需求理解与验收

| 类型 | 当前理解 |
|---|---|
| 真实问题 | 历史数据兼容、软删除恢复、方案适用范围和结果规则之间缺少一致性约束，导致界面成功但列表不可见、可选择后又被服务端拒绝、定性结果误带数值规则等问题。 |
| 明确需求 | 修复编辑；简化方案版本；确保手工计划可见；提前过滤不适用方案；业务中文化；中文文件名；必填标识；结果类型与规则联动。 |
| 涉及对象 | 点检项目、方案版本、设备计划、手工任务、提醒规则、发送记录、导出文件和审计展示。 |
| 可能歧义 | “回退”是否覆盖历史版本。 |
| 默认假设 | 回退不改写历史，而是基于指定历史快照创建并发布一个新版本。 |
| 假设影响 | 版本链可追溯，当前版本单向递增。 |

### Given / When / Then

1. 给定旧点检项目缺少部门字段，编辑保存时，系统使用当前可用组织补齐并对缺失字段给出明确提示。
2. 给定新增或修改方案，点击保存时，系统在同一事务中创建并发布版本；给定历史版本，选择恢复时创建新的已发布版本，不覆盖历史。
3. 给定同一方案和设备曾存在已删除计划，再次手工创建时，系统恢复该记录、更新计划内容并使其重新可见。
4. 给定设备和方案，界面只展示适用于该设备的已发布方案，服务端仍进行二次校验。
5. 给定提醒规则编码不合规，用户看到可理解的中文规则说明，而非正则表达式。
6. 给定发送记录和操作记录，渠道、状态、动作和常见字段以中文业务含义展示。
7. 给定 Excel 导出，下载文件名使用中文业务名称。
8. 给定定性结果类型，仅提供固定业务选项并清除数值上下限；给定“必须数值”，结果类型自动切换为数值并至少要求一个有效数值边界。

## 3. 实施摘要

- 点检项目：兼容旧数据，补充必填标识和前后端一致校验；定性/定量字段联动。
- 点检方案：新增和新版本均直接发布；新增历史版本视图及指定版本恢复；后端使用事务保证创建与发布原子性。
- 点检计划：修复唯一键命中软删除记录后仍保持删除状态的问题；重新创建时恢复并更新记录。
- 手工任务：设备变化后重新加载适用方案，只允许选择匹配方案。
- 业务可读性：提醒规则、发送状态、操作动作和常用字段中文化；导出文件名中文化。
