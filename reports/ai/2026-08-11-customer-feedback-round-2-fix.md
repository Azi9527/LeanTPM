# 2026-08-11 客户反馈第二批修复证据

## 范围与验收

- 点检方案列表提供当前版本“查看明细”，展示方案适用范围及项目执行规则。
- 租户后台统一控制 APP 是否允许从相册选择照片，缺省仅允许现场拍照。
- 设备现场信息页压缩为单屏摘要，管理信息可展开，多任务通过“查看全部”进入列表。
- 设备导入模板使用与单个新增一致的中文业务术语，中文生命周期及五类默认设备分类可导入，同时兼容旧表头和旧英文编码。
- 点检照片校验错误指出项目序号、项目名称、数量/大小/类型原因；允许跳过的项目不再被照片规则拦截。
- APP 对 HTTP 409 查询服务端权威状态；任务仍未完成时保留并重基草稿，只有服务端确认完成才清理草稿。

## 风险与影响

- 综合等级：L4。
- 数据库：新增 V52 纯数据扩展；无表结构修改。
- API：移动端 `photoPolicy` 和后台照片设置新增 `allowAlbumSelection` 字段。
- 权限：沿用 `system:parameter:view/manage`、`inspection:scheme:view`、`equipment:ledger:import` 和 `inspection:task:execute`。
- APP：照片来源、冲突恢复和设备单屏布局。
- Web：方案详情及后台照片开关。

GitNexus 在类/接口聚合层面对 `EquipmentService`、`InspectionMapper` 给出 CRITICAL。实际改动已缩小到设备导入私有路径，以及一个新的只读附件诊断查询；未改变已有 Mapper 方法签名、设备台账公共创建流程或其他状态流。

## 数据保护与回滚

V52 的 SQL 为纯数据 EXPAND、无需停机，但发布分类为 `backwardCompatible=false`：旧 Backend 的 readiness 只接受旧 Schema，不能在 V52 上继续运行；升级必须将 Backend 与 Schema 作为同一发布单元切换。

- 为每个启用且未删除的租户增加内置参数 `mobile.photo-allow-album-selection=false`。
- 为每个启用且未删除的租户增加或恢复五个顶级设备分类：生产设备、环保设备、辅助设备、运输设备、其它设备。
- 唯一键冲突时保留客户现有参数值、分类名称、父级和描述，仅恢复启用状态并标记内置参数。
- 全新安装执行 V1→V52；现有生产路径执行 V50→V51→V52；重复执行必须 no-op。
- 不修改 `flyway_schema_history`，不执行 repair/baseline，不在生产试跑 SQL。
- 发布前必须以隔离 MySQL 验证全新安装、升级、多租户、软删除恢复、校验和及重复执行，并验证备份恢复流程。
- 回滚应用时保留 V52 数据；若必须撤销数据，只能基于发布前备份和精确审计记录人工恢复。

## 残余边界

- “仅相机”是 APP 入口控制，不构成不可伪造的拍摄来源证明。
- 方案历史版本仍引用现有点检项目主数据，不承诺审计级不可变项目快照。
- APP 正式升级包发布前仍需取得新的、严格大于线上 101 的 versionCode；本次未擅自修改版本号或签名。
