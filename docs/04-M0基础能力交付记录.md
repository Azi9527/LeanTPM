## 2. 数据库交付

Flyway 迁移：`V2__system_parameters_and_number_rules.sql`

新增表：

- `system_parameter`：系统参数、值类型、分组、启停状态、内置标识和乐观锁版本。
- `system_number_rule`：编号前缀、日期格式、分隔符、流水位数和重置周期。
- `system_number_sequence`：按租户、规则和周期保存原子流水。

种子数据：

- `system.name`
- `system.timezone`
- `security.captcha.enabled`
- `EQUIPMENT`
- `INSPECTION_TASK`
- `MAINTENANCE_TASK`

所有表均包含租户、创建/更新人、创建/更新时间、逻辑删除和版本字段。自定义参数删除时保留逻辑删除记录，并释放原参数键供后续重新创建。

## 3. 后端交付

系统参数接口：

- `GET /api/v1/system/parameters`
- `POST /api/v1/system/parameters`
- `PUT /api/v1/system/parameters/{id}`
- `DELETE /api/v1/system/parameters/{id}`

编号规则接口：

- `GET /api/v1/system/number-rules`
- `POST /api/v1/system/number-rules`
- `PUT /api/v1/system/number-rules/{id}`
- `POST /api/v1/system/number-rules/{ruleCode}/generate`

核心约束：

- 参数键和规则编码创建后不可修改。
- 参数值按文本、布尔值、整数和小数执行后端类型校验。
- 修改操作使用版本字段实施乐观锁。
- 内置参数允许调整但不允许删除。
- 日期格式和重置周期使用白名单校验。
- 编号流水通过 MySQL 唯一索引、原子递增和事务行锁保证并发安全。
- 流水按每天、每月、每年或永不重置四种方式分段。
- 系统时区通过 `system.timezone` 参数统一读取。

## 6. Redis 认证会话增量

Flyway 迁移：`V3__online_user_permissions.sql`

新增权限：

- `system:online-user:view`
- `system:online-user:kickout`

新增接口：

- `GET /api/v1/system/online-users`
- `DELETE /api/v1/system/online-users/{sessionId}`

实现约束：

- 每个访问令牌和刷新令牌均包含独立 `jti`，一对令牌共享唯一会话 `sid`。
- Redis 会话保存租户、用户、登录 IP、终端、登录时间、最近活动时间、过期时间和当前刷新令牌 ID。
- 刷新令牌通过 Lua 脚本原子校验并轮换，同一刷新令牌只允许成功使用一次。
- 检测到旧刷新令牌重用时撤销整个会话，已经轮换出的访问令牌同时失效。
- 退出登录、修改密码和管理员强制下线均写入会话黑名单，原访问令牌立即失效。
- 修改密码撤销该用户的全部旧会话，然后签发一个新会话。
- 登录失败次数使用 Redis 原子计数和 TTL，在多实例环境中保持一致。
- Redis 不可用时返回 `503 REDIS_UNAVAILABLE`，不降级为不可撤销的无状态 JWT。
- 在线用户页面展示多会话、登录 IP、终端、登录时间和最近活动时间，并禁止管理员从该页面强退自身当前会话。

## 7. 统一数据权限增量

Flyway 迁移：`V4__data_permission_foundation.sql`

新增表：

- `organization`：企业、工厂、车间、产线和班组共用的组织树基础。
- `system_data_scope`：数据范围策略定义。
- `system_role_data_scope`：角色、范围策略和自定义组织关系。

内置范围策略：

- `ALL`：当前租户全部数据。
- `ORGANIZATION`：当前用户所属组织。
- `ORGANIZATION_AND_CHILDREN`：当前组织及全部有效下级组织。
- `SELF`：本人创建、负责或被分派的数据。
- `CUSTOM`：角色显式选择的组织集合。

新增接口：

- `GET /api/v1/system/organizations/tree`
- `GET /api/v1/system/data-scopes`
- `PUT /api/v1/system/roles/{roleId}/data-scope`

新增权限：

- `system:data-scope:view`
- `system:data-scope:manage`

实现约束：

- 用户必须绑定有效组织，用户列表返回组织名称。
- 多角色范围按并集解析；任一有效角色拥有 `ALL` 时直接使用租户全量范围。
- 角色范围每次请求从数据库解析，管理员调整后不要求目标用户重新登录。
- MyBatis 只接收结构化的当前用户 ID 和组织 ID 集合，不接收前端 SQL 或动态列名。
- 用户分页查询和总数查询使用同一数据范围片段，避免记录数泄漏。
- 用户编辑、启停和重置密码先校验目标资源，再在 `UPDATE` 语句中再次附加范围条件。
- 无任何有效范围授权时默认拒绝全部数据，不回退为租户全量。
- 自定义范围必须至少包含一个当前租户内启用的组织。
- 后续设备、点检、维保和 OEE Mapper 复用同一 `DataPermission`，按组织和负责人字段执行约束。
