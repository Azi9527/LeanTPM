## 2. 本轮冻结结论

### 2.1 范围边界

1. 本期交付设备基础和点检管理；设备保养、独立故障/维修工单暂不纳入验收。
2. 已存在的保养、故障和维修能力保留代码，通过功能开关控制，不删除历史表和接口。
3. 扫码设备页只允许进入点检任务和手工创建点检任务；保养、报修入口仅展示禁用态“尚未开发”，不得调用后端业务接口。
4. 点检异常只形成异常记录，不允许在本期从异常创建维修工单。
5. 移动端仅交付 Android APP；不开发 iOS 和微信小程序。
6. 系统部署在客户内网；不采用云端资源；MES、IoT 等外围系统只预留鉴权、幂等和版本化接口规范。

### 2.2 需求编号整理

原表重复使用 `REQ-040`，本规格统一为：

- `REQ-040`：Android APP 范围与兼容要求。
- `REQ-041`：MES、IoT 等外围系统预留接口。
- `REQ-042`：约 200 台设备、500 名注册用户的容量基线。

## 3. 点检主数据与结果

### 3.1 REQ-009 设备信息与变更日志

- 设备主数据暂不建设可恢复的完整版本管理。
- 设备名称、编号、组织、位置等字段变更写入字段级变更日志，记录旧值、新值、人员、时间、来源和备注。
- 不提供主数据“恢复历史版本”功能。
- 点检任务仍保留生成时设备名称和设备编号两个只读单据字段，避免已完成报表随台账改名而变化；该快照不形成独立历史版本页面。

### 3.2 REQ-010 两层/三层点检结构

- 支持 `设备 → 点检项目` 两层结构。
- 支持 `设备 → 部位 → 点检项目` 三层结构。
- 点检部位允许为空；无部位项目在执行端归入“通用点检”。
- Web、Android、导入模板和导出结果使用同一结构规则。

### 3.3 REQ-013 结果类型

最终业务结果统一为“合格/不合格”，录入方式分为：

1. 定性：执行人直接选择合格或不合格。
2. 定量：执行人录入数值；系统根据任务快照中的下限、上限和单位自动判断合格或不合格。

定量结果必须保存原始数值、单位、上下限、自动判定结果和最终结果。超限自动生成异常；人工覆盖自动判定必须具备权限并填写原因。

### 3.4 REQ-014 异常与设备停机联动

- 点检项目配置“异常默认停机”规则，方案项目可以覆盖该规则。
- 任务生成时固化停机规则快照。
- 执行人提交不合格结果时可以勾选或取消“设备需要停机”，但偏离默认规则必须填写原因。
- 确认停机后将设备状态变更为 `STOPPED`，记录变更前后状态、操作者、时间、来源任务、异常和原因。
- 本期异常只做发现、责任人、期限、措施、验证、关闭和复开，不创建维修工单。

### 3.5 REQ-015～017 照片、附件和水印

- 点检结果和异常均支持上传、预览、下载图片或附件。
- 项目可配置是否必拍、最少/最多数量、单文件大小、允许类型和压缩质量。
- Android 保存原图和水印图；默认查询、预览、导出使用水印图。
- 水印包含客户品牌、设备名称/编号、任务编号、执行人、服务端校准时间和设备故障位置/部位文字。
- “定位”指设备故障位置或设备部位，不是经纬度；正式 Android 包移除粗略/精确定位权限及 GPS 强制校验。
- 原图只允许授权管理人员查看，并记录访问审计。
- 断网附件进入加密离线队列，恢复网络后使用客户端请求 UUID 幂等上传。

## 4. 导入、历史和计划日历

### 4.1 REQ-018 覆盖更新与行级历史

- 使用 `tenant_id + 业务编码` 判断相同记录。
- 新编码新增；相同编码覆盖当前值。
- 每一行提供“历史记录”入口，记录变更前后值、修改人、时间、来源、导入批次和备注。
- 导入继续采用“仅校验 → 预览 → 确认提交”流程。
- 已发布方案的相同编码更新产生新方案版本，不修改已生成任务的标准和结果快照。
- 重复提交同一导入批次不得产生重复版本或重复关系。

### 4.2 REQ-019 工作周和自由日历

新增生产日历能力：

1. 工作周：设置周一至周日每一天为工作日或休息日。
2. 自由日历：按单日或日期范围设置工作日/休息日，并填写名称，例如“国庆节”“厂庆”“临时检修”。
3. 自由日历优先级高于工作周。
4. 相同日期存在冲突配置时，以优先级更高、更新时间更晚的有效规则为准，并记录冲突日志。
5. 休息日默认不自动生成计划任务；授权人员仍可扫码或后台手工创建临时任务。

### 4.3 方案提前生成配置

- 每个点检方案维护 `generation_lead_minutes`，不再依赖全局固定提前天数。
- 页面允许按分钟、小时、天输入，服务端统一转换为分钟保存。
- 默认提前 60 分钟，合法范围为 0～43200 分钟（30 天）。
- 调度器每 5 分钟扫描一次，当前时间进入“计划时点减提前量”窗口后生成任务。
- 唯一键使用租户、设备、方案版本、计划时点，保证一个计划时点只生成一张任务。
- 服务停机恢复后，只补生成仍在允许补生成窗口内的任务；规则由方案配置。

## 5. 任务创建、派工和提交

### 5.1 自动与扫码手工创建

- Android 扫码识别设备后展示当前用户可见的点检任务。
- 扫码页提供“创建点检任务”，只列出对该设备适用且已发布的点检方案。
- 手工创建选择执行人、截止时间和班组；重复点击使用幂等键防止重复任务。
- 保养、报修入口保持禁用并显示“尚未开发”。

### 5.2 多人任务

- 任务支持一个或多个执行人，第一位仍作为主执行人用于列表展示和统计。
- 主执行人和协作人都可以编辑和提交。
- 任意执行人首次成功提交后，整个任务完成。
- 首次提交使用幂等键、数据库条件更新和乐观锁；其他人再次提交返回明确的“任务已由某人于某时完成”，不得覆盖结果。
- 提交前保存最后修改人；提交后的更改必须通过复核退回流程。

## 6. 提醒规则

### 6.1 REQ-021～024 通知范围

- 通知渠道仅实现系统站内消息和 Android 系统通知。
- 短信、邮件、企业微信不在本期范围。
- 临时点检提醒通过规则配置：触发事件、提前时间、重复间隔、最大次数、接收对象、级别、是否确认、确认时限、免打扰和升级规则。
- 任务超过截止时间立即标记逾期并提醒执行人。
- 逾期只升级到班组长，不默认升级车间主任。
- 任务完成、取消或作废后停止通知。
- 同一任务、规则、接收人和时间窗口只生成一条消息。

## 7. 用户、权限与设备可见范围

| 身份 | 功能权限 | 数据范围 |
|---|---|---|
| 超级管理员 | 全部系统与业务权限 | 全部数据 |
| 管理人员 | 所在组织全部业务管理权限；系统参数默认不可修改 | 所在组织及下级 |
| 班组长 | 除系统管理模块外的全部业务权限 | 所属班组 |
| 员工 | 任务执行、反馈、附件、异常上报、个人报表 | 本人任务和个人报表 |

- 员工暂时可以只读查看全部设备基础资料和当前状态。
- 员工不得新增、编辑、删除、转移设备或变更设备状态。
- 菜单/按钮权限和服务端数据权限必须同时校验；不能仅隐藏页面元素。
- 用户导入后首次登录必须修改初始密码。

## 8. 二维码与结果导出

### 8.1 二维码

- 每台设备只有一个当前有效二维码。
- 标签宽度、高度可配置，单位为毫米。
- 系统根据尺寸自动排版客户 Logo、二维码、设备名称和设备编号。
- 输出 PNG，默认 300 DPI，并保留二维码静区。
- 支持全部设备一键生成、批量选择和批量图片下载；不接打印机、MES 或 IoT。

### 8.2 Excel 嵌入图片

- 导出界面提供“包含图片”选项。
- 选择后把水印图嵌入 Excel，不嵌入原图。
- 多图按结果行或独立图片明细页排列，并与任务、项目、异常建立可见关联。
- 超过 1000 张图片或预计文件超过 200MB 时必须异步生成并拆分工作簿。
- 查询和导出使用完全相同的数据范围；图片加载失败必须在工作簿中标记，不得静默丢失。
- Excel 文本继续防公式注入。

## 9. 看板

- PC 看板支持日、周、月口径和任务/异常明细下钻。
- 每天 00:05 刷新聚合缓存，并提供授权手工刷新；任务列表和执行页始终实时查询。
- 指标包括设备状态、应检、完成、待办、逾期、异常、完成率和按时率。
- Android 重点展示设备状态、点检任务进度、异常、本人任务和个人报表。
- 超级管理员看全部；管理人员看所在组织及下级；班组长看班组；员工看本人指标。

## 10. 本地部署和容量基线

### 10.1 标准生产服务器

| 项目 | 生产要求 |
|---|---|
| CPU | 8 核以上，主频不低于 2.4GHz |
| 内存 | 32GB ECC |
| 系统/应用盘 | 2×960GB 企业级 SSD，RAID1 |
| 数据库空间 | 独立 300～500GB 高性能卷 |
| 附件盘 | 4×4TB 企业级盘，RAID10，约 8TB 可用，或同等级企业 NAS |
| 独立备份 | 不少于 12TB，不能与生产数据位于同一故障域 |
| 网络 | 双千兆网卡，客户端只开放 HTTPS 443 |
| 操作系统 | Ubuntu Server 24.04 LTS、Rocky Linux 9 或 AlmaLinux 9，x86_64 |
| 运行环境 | OpenJDK 21、MySQL 8、Redis 7、Nginx |

- JVM 初始建议 `-Xms2g -Xmx6g`；MySQL Buffer Pool 10～12GB；Redis 最大内存 1GB。
- MySQL 开启 binlog；数据库每日全量、15 分钟增量；附件每日增量、每周全量。
- 目标 `RPO ≤ 15 分钟`、`RTO ≤ 4 小时`，每季度恢复演练。
- 100 并发持续 30 分钟，业务接口错误率低于 0.5%，普通查询 P95 不超过 2 秒。
- 附件容量按原图和水印图双份测算；使用率达到 70% 预警、80% 告警。

## 11. Android 基线

| 项目 | 要求 |
|---|---|
| 最低系统 | Android 10 / API 29 |
| 推荐系统 | Android 12～Android 16 / API 31～36 |
| 编译/目标 SDK | compileSdk 36、targetSdk 36 |
| CPU | arm64-v8a，64 位 ARM 八核 |
| 内存 | 最低 4GB，推荐 6GB 以上 |
| 存储 | 最低 64GB 且 2GB 可用，推荐 128GB 且 5GB 可用 |
| 屏幕 | 最低 5.5 英寸、720×1280，推荐 1080P |
| 摄像头 | 后置 800 万像素、自动对焦，推荐 1200 万像素以上 |
| 网络 | 5GHz Wi-Fi 或 4G，推荐 Wi-Fi 5/6 + 4G/5G |

- 验收覆盖小米/Redmi、OPPO/一加、vivo/iQOO、荣耀、三星及 Android 兼容工业终端。
- 华为设备只有在能够正常安装和运行 Android APK 时纳入本期；HarmonyOS NEXT 原生应用不在范围内。
- 正式权限只保留网络、相机和 Android 13+ 通知；不申请 GPS 和全盘存储权限。
- 正式包只连接受信任 HTTPS，支持企业 MDM 或内网下载中心分发。
- 客户持有企业签名；同一包名升级使用同一签名；每次发布记录 APK 和签名证书 SHA-256。
- 普通版本可选升级；安全漏洞和接口不兼容版本强制升级。

## 12. 迁移规划

已经执行的 `V1～V24` 不修改。后续建议：

| 迁移 | 主题 |
|---|---|
| V25 | 会后整改基础：功能开关、日历、方案提前量、行级历史 |
| V26 | 异常停机规则、结果快照和多人提交约束 |
| V27 | 故障位置文字水印、附件规则和 GPS 字段兼容降级 |
| V28 | 权限模板、设备只读范围、看板日/周/月口径 |
| V29 | 异步导出、图片嵌入任务和文件拆分元数据 |

实际迁移可以按开发依赖拆分，但必须保持版本单调递增和已执行脚本不可变。

## 14. 实施顺序与门禁

1. 更新规格、需求编号和追踪矩阵。
2. 实现工作周、自由日历和方案提前生成时间。
3. 重构自动/扫码手工任务生成和幂等。
4. 实现多人任务首次提交完成的并发规则。
5. 实现异常停机联动并调整扫码禁用入口。
6. 移除 Android GPS 权限和逻辑，改为设备故障位置文字水印。
7. 实现 Excel 嵌入水印图片和异步拆分。
8. 实现权限、设备只读和日/周/月看板下钻。
9. 完成二维码、部署、Android 兼容、全量自动化和验收报告。

每一步必须完成数据库迁移测试、后端单元/集成测试、前端类型检查和构建；涉及 Android 时追加 Android 单测、Debug APK 构建和真机待验清单。只有自动化结果与人工验收证据同时记录后，追踪状态才能改为“完成”。
