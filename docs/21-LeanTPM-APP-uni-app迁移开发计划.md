# LeanTPM-APP uni-app 迁移开发计划

## 1. 计划目标

以可运行、可回归、可回退为门禁，把现有移动能力迁入 `LeanTPM-APP`。每个批次独立提交 Git，批次完成条件包括代码、自动化、HBuilderX 构建证据和验收记录，不以“页面已写”代替完成。

## 4. 每批开发流程

1. 读取当前服务端 DTO、权限和错误码，不复制猜测字段。
2. 先实现纯逻辑及单测，再接页面。
3. 运行 JS/JSON 静态检查、单测和目标平台构建。
4. 在 Android 基座验证本批主路径和失败路径。
5. 更新本计划状态及验收证据。
6. `git diff --check` 后只暂存本批文件，排除客户 Excel 和临时文件。
7. 使用 `feat(app): ...` 或 `docs(app): ...` 独立提交。

## 5. 完成定义

- 代码中不存在 `@capacitor/*`、Element Plus、Vue Router、直接 DOM 和 GPS 引用。
- Android 最终权限清单只包含经批准的网络、相机、通知及框架必要内部权限。
- 所有写操作具备稳定幂等键；401 刷新不会并发放大。
- 服务切换、退出和用户切换不会串用 Token、草稿或照片队列。
- 定性/定量、多人提交、异常停机、水印和附件遵循现有服务端规则。
- H5、微信开发构建和 Android 调试/发行构建结果均记录。
- 现场无法执行的企业签名、客户真机和生产 HTTPS 验收必须明确列为待验，禁止伪造通过。
