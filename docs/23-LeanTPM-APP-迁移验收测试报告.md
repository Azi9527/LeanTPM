# LeanTPM-APP uni-app 迁移验收测试报告

## 1. 验收结论

截至 2026-08-04，`LeanTPM-APP` 已完成从原 Vue/Capacitor WebView 移动端到经典 uni-app Vue 3 工程的代码迁移。Android 为本期交付端，同时保留 H5 与微信小程序编译能力；原 PC Web 和原 Capacitor Android 基线未删除，可用于回退和业务口径对照。

本轮代码静态检查、11 项自动化测试、H5、微信小程序、App 资源编译以及真实后端只读接口冒烟测试全部通过，未发现阻断交付的 P0/P1 代码缺陷。企业签名 APK、生产 HTTPS、微信 AppID、客户真机矩阵和双终端并发属于外部环境验收项，不能用开发机结果代替，已在第 7 节单列。

## 5. 真实接口冒烟结果

开发机后端监听 `18080`，MySQL 使用本机 `3306`，Redis 恢复后使用管理员账号执行只读冒烟，未提交或改变点检业务数据。

| 接口 | 结果 | 证据摘要 |
|---|---|---|
| `POST /auth/login` | 通过 | 返回管理员用户和有效访问令牌 |
| `GET /mobile/bootstrap` | 通过 | 返回移动工作台数据 |
| `GET /equipment?page=1&pageSize=3` | 通过 | 当前总数 8 |
| `GET /inspection/tasks?mineOnly=true&page=1&pageSize=3` | 通过 | 当前本人任务总数 1 |
| `GET /notifications/messages?page=1&pageSize=3` | 通过 | 当前消息总数 2 |

测试中首次登录返回 503，定位为电脑重启后 Redis 未运行；启动本机 Redis 后以上接口全部通过。该行为符合系统“认证会话不允许退化到不可撤销的无状态令牌”的安全设计，不属于 APP 缺陷。

## 6. Android 真机与权限证据

- 已识别并运行过的开发机设备：vivo `V2429A`，Android 16；历史真实登录日志包含该设备 WebView 标识。
- HBuilderX 已识别 `LeanTPM-APP - vivo V2429A`，Android App 标准基座曾正常启动并产生 `App Show` 日志。
- 最终版本发起再次运行时 USB/ADB 设备列表变为空，因此没有将“最终真机扫码、相机、飞行模式”伪记为通过；恢复 USB 调试连接后按第 7 节复验。
- manifest 显式业务权限只有 Internet、网络状态和 Camera；不声明精确/粗略定位、通讯录、短信、电话状态、读取日志或外部存储读写权限。
- 相机被声明为非强制硬件特性，便于无相机测试终端安装；扫码与拍照入口仍会在运行时检查能力。

## 7. 发布前外部验收清单

以下事项依赖客户资料、生产环境或现场设备，不影响代码迁移完成状态，但正式发布前必须关闭：

1. 恢复手机 USB 调试后，在 vivo V2429A 上重新运行最终工程，验证服务地址、登录、扫码、拍照水印、附件预览和断网恢复。
2. 使用至少两台账号有同一任务的终端并发提交，验证任一执行人提交后任务完成，另一端收到已完成刷新提示。
3. 按 Android 10、12、13、14、15、16 与客户主流品牌/工业终端矩阵执行兼容验收。
4. 提供原 `com.leantpm.mobile` 正式签名 JKS、别名与安全保管的密码，在 HBuilderX 发行流程生成企业签名 APK；本报告不把 App 资源编译等同于签名 APK。
5. 部署受信任 HTTPS 服务地址，配置生产域名、证书、CORS 和反向代理；生产包不得依赖局域网 HTTP。
6. 提供微信小程序 AppID、合法 request/upload/download 域名并完成隐私声明后，在微信开发者工具和真机预览验收。
