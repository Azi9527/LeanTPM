| 表 | 用途 |

| `visualization_scene_node` | 组织、设备、装饰节点的业务绑定与三维变换 |

- 7 个程序化模型资源；
- 1 个工厂、2 个车间、4 条产线、7 个场景和 14 个节点；
- 8 台独立分类的演示设备及动态状态；

演示设备使用独立根分类 `VISUALIZATION-DEMO`，不会进入既有点检或维保方案的分类递归适用范围。

## 3. 后端能力

新增 `com.leantpm.visualization` 领域模块：

- `VisualizationController`
- `VisualizationService`
- `VisualizationStreamService`
- `VisualizationMapper` 与 XML
- `VisualizationDtos`

接口前缀为 `/api/v1/visualization`。

主要接口：

| 资源 | 能力 |
|---|---|
| `/dashboard` | 一次返回核心指标、状态分布、组织态势、实时设备、点检、维保和 OEE |
| `/stream` | 只发送刷新信号的 SSE 通道，业务数据仍通过授权聚合接口读取 |
| `/scenes`、`/scenes/{id}` | 场景目录、面包屑、节点、模型与状态色 |
| `/equipment/{id}/snapshot` | 设备状态时长、今日运行/停机/OEE、任务、异常和最近活动 |
| `/models` | 模型目录 CRUD、GLB/GLTF 上传和授权内容代理 |
| `/scenes`、`/nodes` | 场景与节点 CRUD、乐观锁及引用保护 |
| `/status-colors` | 状态显示色、发光色、脉冲和排序维护 |

聚合查询复用统一 `DataPermissionService`，不接受请求拼接 SQL。场景和节点写操作校验组织范围，设备节点校验设备可访问性，所有写接口均使用动作级权限和幂等键。

## 4. 大屏与三维页面

新增页面：

1. 设备综合运行驾驶舱；
2. 三维设备运行中心；
3. 设备状态监控大屏；
4. 点检运营分析大屏；
5. 维保运营分析大屏；
6. OEE 效率分析大屏；
7. 三维场景配置。

大屏支持：

- 组织、开始日期、结束日期筛选；
- 配置化自动刷新、SSE 触发刷新与定时降级刷新；
- 全屏模式和响应式布局；
- 状态、组织、点检/维保趋势、OEE 趋势、排名与损失图表；
- 设备实时列表、长时异常突出显示和台账下钻；
- 空数据、加载、错误和无权限路由处理。

三维场景支持：

- 工厂 → 车间 → 产线 → 设备下钻和面包屑返回；
- OrbitControls 旋转、缩放和平移；
- GLB/GLTF 加载、授权文件下载、状态着色；
- 模型失败时自动退化为工厂、车间、产线、CNC、机器人、压力机、泵站等程序化模型；
- 设备点击快照和完整台账链接；
- 按场景加载，Three.js 独立懒加载包，不进入主页面首屏包。

## 7. 已知限制

- V1 的实时刷新由 SSE 刷新信号与定时回退组成，设备状态仍来自业务状态表；IoT 直连将在后续集成阶段实现；
- `.gltf` 若引用外部分片或纹理可能因单文件存储缺少依赖而退化为程序化模型，生产模型建议使用单文件 `.glb`；
- ECharts 和 Three.js 均已路由懒加载，但框架主依赖包仍约 1.23 MB，Vite 会给出非阻断体积提示；
- 本阶段采用数据库直接聚合和固定次数查询，未增加 Redis 业务数据缓存；刷新频率由参数限流，M7 压测后再按热点查询决定缓存键与失效策略。
