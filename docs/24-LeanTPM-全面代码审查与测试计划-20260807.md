# LeanTPM 全面代码审查与测试方案及计划

## 1. 文档信息

- 版本：V1.0
- 编制日期：2026-08-07
- 适用范围：LeanTPM PC Web、Java 后端、LeanTPM-APP（uni-app）、MySQL 数据库及本地部署服务
- 固定开发端口：PC 前端 `15173`、后端 `18080`、MySQL `3306`

## 2. 测试目标

1. 验证认证、菜单权限、组织数据权限在 PC、APP、接口和报表中的口径一致。
2. 验证设备、点检、附件、异常、消息、报表等核心业务形成可追溯闭环。
3. 验证数据库迁移、逻辑删除、导入覆盖和历史记录不会产生脏数据或数据泄漏。
4. 验证 PC 与 APP 在服务不可用、弱网、重复提交和跨端操作时能够安全降级。
5. 建立可重复执行的自动化回归基线，修复审查和测试发现的缺陷。

## 3. 测试范围

### 3.1 后端与数据库

- 登录、验证码、JWT、密码锁定、密码修改及超级管理员全权限。
- 组织树、车间主任、班组长、员工多班组关系与上下级关系。
- 数据权限：管理员全量；管理人员本组织及下级；班组长本班组及下属；员工个人任务。
- 设备台账、设备条码、设备状态及组织筛选。
- 点检项目、方案、计划、任务、执行、异常、统计、历史与逻辑删除。
- 附件上传、下载、预览、水印、原图保留及业务对象访问权限。
- 消息提醒、逾期升级、上级领导接收和只读详情。
- Flyway 迁移、唯一约束、事务、并发幂等和导入覆盖规则。

### 3.2 PC Web

- 登录、品牌、菜单开关、路由守卫、记住账号和密码。
- 复合表头数据库查询、排序、字段显隐和字段顺序。
- 设备条码/设备状态按组织查询及统计与明细一致性。
- 点检计划、任务、我的点检、异常、统计及附件预览。
- 工作台指标、待办、异常消息与业务明细下钻。
- 大屏、三维场景的加载、降级提示和远程浏览器兼容性。

### 3.3 LeanTPM-APP

- 服务地址保存与测试、登录、离线提示、会话失效和安全退出。
- 首页待办、设备状态、扫码、设备全景信息、直接登记点检。
- 点检任务列表、执行、草稿、整单图片、项目附件、异常和完成概况。
- 相机/相册多选、必传图片、最大张数、水印与 PC 端可见性。
- 个人报表日期快捷查询、组织数据范围及完成/异常统计。

## 4. 测试策略

| 层级 | 方法 | 目标 |
| --- | --- | --- |
| 静态审查 | 编译、类型检查、依赖、权限调用链、SQL 与事务审查 | 提前发现越权、空值、统计口径和兼容问题 |
| 单元测试 | JUnit、Node 测试 | 覆盖纯逻辑、边界值、日期、状态机和数据权限计算 |
| MySQL 集成测试 | 独立临时数据库、完整 Flyway、真实 Mapper/Service | 验证 SQL、迁移、事务、逻辑删除和数据库过滤 |
| API 测试 | 不同角色 JWT 调用相同接口 | 验证功能权限和数据权限均不可绕过 |
| PC/APP 流程测试 | 浏览器、Android 真机 | 验证关键业务闭环和用户可理解提示 |
| 非功能测试 | 并发、弱网、大数据量、安全与恢复 | 验证生产可用性和失败恢复能力 |

## 5. 风险与优先级

- P0：跨租户/跨组织越权、管理员无权限、附件泄漏、逻辑删除数据仍可见、点检结果丢失或重复。
- P1：统计与明细不一致、异常未升级、日期边界错误、图片上传/预览失败、扫码范围错误。
- P2：展示、文案、字段顺序、响应式布局、可视化降级和轻微性能问题。

## 7. 非功能测试

1. 性能：4 核 8 GB 环境下 50 并发查询、10 并发点检提交；P95 查询小于 2 秒，提交小于 3 秒。
2. 容量：至少 10 万任务、100 万点检结果、10 万附件元数据下验证分页和索引。
3. 安全：对象 ID 横向越权、恶意文件名、文件类型伪造、超大文件、SQL 注入、XSS、CORS 和 Host 头。
4. 可靠性：重复点击、网络超时、服务重启、MySQL 断连和上传中断；事务不产生半成品。
5. 兼容性：Chrome/Edge 当前主流版本；Android 10 及以上，重点覆盖 Android 12～16。

## 8. 执行计划

### 阶段 A：基线与静态审查

- 盘点未提交改动、配置、迁移和测试资产。
- 执行前端类型检查/构建、APP 校验、后端单元测试。
- 审查数据权限、附件权限、公共接口、逻辑删除和统计 SQL。

### 阶段 B：数据库与接口集成

- 在唯一临时 MySQL 数据库执行全部 Flyway 迁移。
- 执行 Mapper/Service 集成用例，并补充审查发现的边界用例。
- 使用管理员、上级组织、班组长、员工身份验证同一资源。

### 阶段 C：端到端业务回归

- PC：登录 → 设备 → 方案 → 计划/登记 → 执行 → 异常 → 消息 → 报表。
- APP：服务配置 → 登录 → 扫码/待办 → 图片 → 提交 → 历史/异常/报表。
- 验证统计卡片、列表、明细和导出一致。

### 阶段 D：缺陷修复与复测

- 按 P0、P1、P2 顺序修复；每个缺陷至少新增一个自动化或可复现回归用例。
- 全量重跑构建、单元测试、MySQL 集成测试和关键浏览器流程。

## 10. 准出标准

1. P0 缺陷为 0；P1 缺陷全部修复或有客户确认的规避方案。
2. PC、APP 构建和后端打包成功。
3. 后端单元测试、MySQL 集成测试、APP 自动化测试全部通过。
4. 管理员、上级组织、班组长、员工四类账号关键流程回归通过。
5. 服务在 `15173/18080` 可访问，健康检查、登录和核心接口正常。
6. 输出缺陷清单、修复说明、测试证据和遗留风险。
